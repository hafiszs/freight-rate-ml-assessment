# Freight Rate Prediction — Spotter ML Engineer Assessment

Freight rate prediction (`posted_rate`) based on historical data from January–October 2025, used to predict 12,000 loads in `validation.csv` (November–December 2025) and to simulate daily rates for the fixed Lexington → Fort Wayne route throughout December 2025.

**Model:** LightGBM Regressor, predicting the `log1p(posted_rate)` target.

## How to Run

### 1. Set Up the Environment

Using a virtual environment is recommended to avoid dependency conflicts with other Python packages installed on your system.

**macOS / Linux:**

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt

```

**Windows (PowerShell):**

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install --upgrade pip
pip install -r requirements.txt

```

*Note: `requirements.txt` already includes `jupyter` and `ipykernel`, so no additional installation is required to run the notebooks.*

### 2. Run the Notebooks

Launch Jupyter from within the virtual environment:

```bash
jupyter notebook

```

*Alternatively, use `jupyter lab`, or open the project folder directly in VS Code / PyCharm and select the `.venv` interpreter as the kernel.*

Run the notebooks sequentially from top to bottom using **Run > Run All Cells** or the **Restart Kernel and Run All** option:

1. `notebooks/01_eda.ipynb` — Exploratory Data Analysis. This notebook does not generate any output files and is purely analytical.
2. `notebooks/02_modeling.ipynb` — Data cleaning, feature engineering, model training, evaluation, and final prediction generation.

The second notebook automatically generates:

* `validation_predictions.csv` in the project root.
* `data/december_chart_inputs.csv` with the `predicted_rate` column populated.
* `scorer_results/candidate_december.png` by executing `score.py` in the final notebook cell and displaying the chart inline.

There is no need to run anything separately from the terminal for the notebooks. Simply open the notebook and click **Run All**. All cells—including package verification, data loading, model training, and output generation—will execute in sequence.

## Approach Summary

### Data Quality Issues Identified and Addressed

* **Negative weight values:** 292 rows contained negative weights. These were confirmed to be sign errors because their absolute magnitudes matched corresponding positive values. They were corrected using `abs()`.
* **Missing weight and market_index values:** Approximately 0.6–0.8% of values were missing. `weight` was imputed using the median within each equipment category, while `market_index` was imputed using an annual seasonal curve.
* **Inconsistent distance values:** 22 rows had distances inconsistent with straight-line distances calculated from their coordinates. These rows were left unchanged as the sample size was minimal and tree-based models are naturally robust to this level of noise.
* **Unseen cities in validation:** 8 cities in `validation.csv` did not appear in `train_test.csv`. To reduce over-reliance on exact city names, geographic coordinates (`lat` / `lon`) were leveraged as primary spatial features.
* **Missing market_index / quote_signal in December inputs:** `december_chart_inputs.csv` does not contain `market_index` or `quote_signal`. These values were estimated using an annual seasonal curve generated via harmonic regression on `day_of_year`, fitted on `train_test.csv`.

---

### Train / Validation Split

A temporal (time-based) split was implemented instead of a random split:

* **Training:** January–August 2025
* **Internal Holdout:** September–October 2025
* **Final Training:** January–October 2025

The September–October holdout was used for early stopping and evaluation. This setup simulates the target evaluation scenario where the model generalizes to future, unobserved months (`validation.csv` and the December simulation correspond to November–December 2025).

After hyperparameter tuning and model selection, the final model was retrained on the complete January–October 2025 dataset prior to generating final predictions.

---

### Model Choice

**LightGBM Regressor** was selected as the core algorithm, modeling the log-transformed target `log1p(posted_rate)`.

**Key motivations:**

* High robustness to outliers and feature noise identified during EDA.
* Effective modeling of non-linear interactions (e.g., `equipment` $\times$ `distance` $\times$ `season`) without requiring manual scaling.
* Native handling of categorical variables and missing values.
* Proven strong performance on tabular datasets with heterogeneous feature types.
